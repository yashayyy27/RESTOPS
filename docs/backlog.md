# Prioritised backlog

Priorities represent analyst judgement for the fictional case study. No sponsor
approval or stakeholder prioritisation session is claimed.

| ID | Priority | Item | Delivery status | Rationale |
|---|---|---|---|---|
| P01 | Must | Local interactive management app | Implemented; validation recorded separately | Connect investigation to decisions |
| P02 | Must | Reconciled volume/basket/cost bridge | Implemented | Explain observed commercial changes without invented causes |
| P03 | Must | Six-driver profit scenarios and break-even | Implemented | Estimate an action under explicit assumptions |
| P04 | Must | Hourly planning and budget trade-offs | Implemented | Use forecasts for roster discussions |
| P05 | Must | Forecast store metrics and uncertainty | Implemented | Make model quality assessable by restaurant |
| P06 | Must | Promotion evaluation and isolated truth check | Implemented | Evaluate contribution and expose method error |
| P07 | Must | Contracts, audit, hashes, tests and CI | Implemented | Prevent silent financial errors |
| P08 | Must | BA traceability, stories and UAT pack | Implemented | Link requirements to evidence and acceptance criteria |
| P09 | Should | Portable demo, downloads and interview walkthrough | Implemented | Demonstrate without millions of raw rows |
| P10 | Should | Native Tableau workbook | Not implemented | Prepared data/specification support a future build |
| P11 | Could | Intervention register with measured outcomes | Future | Requires real pilot observations; no fabricated outcomes |
| P12 | Could | Skills/availability/award-constrained roster optimisation | Future | Current hourly suggestions are deliberately not rosters |
| P13 | Could | Authorised live-source refresh and production security | Future / out of current scope | Would require source contracts, credentials and operational approval |
| P14 | Could | Promotion randomisation and pre-trend sensitivity | Future | Observational estimates cannot establish causal ROI |

Definition of done: calculation answers a named decision, assumptions/grain are
documented, relevant tests pass, UI has usable outputs and limitations, and
traceability/UAT records reflect actual validation. Implementation status alone
does not imply stakeholder acceptance.
